# 成就系统 · 设计

日期：2026-10-08
状态：已批准，执行中

## 目标

从现有数据（行程 / 打卡 / 照片 / 记账）里算出游戏化徽章：**个人为主 + 全队共享**。
纯计算，不落库、零调度；解锁时间从数据时间戳反推。

## 数据归属（唯一的底层改动）

- `checkins`、`photos` 各加一列 `member_id`（`ensureColumn` 平滑迁移）。
- 写入时取 token 里的 `mid`；没有则按 token 里的名字反查成员。
- **老数据追认**（已确认）：启动迁移时，`member_id IS NULL` 的行统一填
  「创建者」——该旅行**最早加入的成员**（通常就是"我"）。幂等，每次启动兜一遍。
- 快照与照片列表带出 `member_id`。

## 成就目录

**个人（每名成员一套）**：出发咯（首次打卡）、旗开得胜（完成首项）、五子登科
（完成 ≥5）、走过三站（≥3 个不同行程点打卡）、第一张照片、十张照片、三日影像
（≥3 个日期有上传）、早起鸟（07:00 前打卡，本地时间）。

**全队**：全部完成、完美一天（某天全完成且 ≥2 项）、准备就绪（前置全勾完）、
一个不落（待办全清空）、行程过半、影像库（照片 ≥50）、量入为出（旅行结束后
未超预算）、结伴同行（成员 ≥2）。

徽章：`{ id, scope, title, desc, icon, color, done, at, progress }`；条件全部单调
（只从无到有，不回退）。

## 计算

`core/achievements.js`（纯逻辑，两端共用）：输入快照 + now，输出
`{ team, byMember, memberList }`。解锁时间：第 N 张照片的 `created_at`、
完成项的打卡时间等；推不出的（如"量入为出"）`at=null`，UI 不显示日期。

## 展示（Web）

- 设置页「成就」入口，副标题显示我的解锁数；弹层顶部切换：全队 / 我 / 其他成员。
- 两列徽章网格：未解锁灰显 + 进度条（3/10）；已解锁显示 ✓ 与达成日期。
- **解锁庆祝**：快照刷新后对比本机已读记录（`platform.storage` meta），新解锁的
  toast 一次；升级后首次加载只记录不弹，避免一次炸出一堆。
- 小程序端下一轮做，core 模块已备好。

## 测试

- server smoke：打卡/上传后 `member_id` 落上（token 的 mid）。
- `check:core`：个人归属、进度、全队条件、早起鸟（用本地时间构造 ISO，跨时区稳定）。
- smoke（Web）：设置页有成就入口、弹层能开、徽章数 > 0。
