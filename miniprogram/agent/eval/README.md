# agent/eval · 评测集说明

`cases.json` 是给微信「评测插件」的自测/提审评测文件（结构与官方模板一致：
`cases[{intent, tags}]` + `entities[{type, content, source}]`）。

## 怎么用

1. 微信开发者工具（Nightly Electron Build）→「编译模式」切到「**小程序 AI 编译**」→ 打开评测插件；
2. 评测版本：自测会列出最近上传的开发版（先上传一版含 agent 分包的开发版）；
3. 上传 `cases.json` → 过「评测文件检测」→ 生成用例 → 生成轨迹 → 出报告；
4. 报告建议先修「服务交付」再修「体验交互」，改完用「重跑失败用例」。

## 维护注意

- **接口覆盖度**：官方要求 ≥85% 的原子接口被用例触达。当前 14 个接口，
  改动接口集时同步补用例；删除类接口（deleteItem / deleteExpense）如拉低评分，
  可在评测插件里用「接口黑名单」屏蔽。
- **复杂用例 ≥30%**：同目标多条件的用例（如「明天几点出发，上午有安排吗」）。
- **时间标签**：相对时间 `relative-time`、绝对时间 `absolute-time` 至少各有 1 条。
- **未注册场景**：`tags: ["unregistered"]` 的用例不会被自动执行，需要人工核验——
  用**未登录且无数据的空白测试号**走一遍，分别覆盖"同意登录/拒绝登录"两种走向。
- 用例里的地名（玉龙雪山、束河古镇等）与测试行程数据应对得上；换测试行程时把
  实体名同步替换。
- 提审评测（微信团队评测）要求：Intent ≥50 条、全部检测项通过——届时把本文件扩充到
  50+ 条再提交。
